The current interface

PPT deep-reading workspace

The main application canvas is a dedicated PPT reading workspace based on the analyzed twelve-slide TCH matrix course deck. It combines sectioned slide thumbnails, text search, keyboard and pointer paging, zoom, fullscreen, bookmarks, summaries, extracted text and speaker guidance. The visual workspace remains available beside the existing collapsible AI chat, but contains no separate AI action button or AI reading card.

The Files browser is an independent left-edge overlay drawer rather than a block inside the slide thumbnails. Closing the drawer reduces it to a narrow Files tag; selecting that tag restores the same in-memory folder and PPT selection. A user-initiated native directory picker can list folders and PPT/PPTX names only, navigate into child folders, return through the current session history and switch root folders. It does not persist directory handles, upload file data or claim to parse a selected presentation.

Presenter mode opens a separate same-origin window at the current slide. It includes the current slide, next-slide preview, speaker notes, elapsed timer, keyboard navigation, notes visibility, timer reset and direct fullscreen entry. The reader and presenter synchronize slide changes when the browser supports BroadcastChannel.

The current implementation is a complete frontend reading design with representative local content. Real arbitrary PPT/PPTX parsing remains a later integration.

Open the running application

AI conversation

The right-side chat continues to render Markdown, GFM tables, local KaTeX mathematics, attachments and tool progress. It can collapse to give the PPT workspace more reading room, and its session, stop, retry, rename and restart behavior is unchanged.

Progress and updates

The default total-turn deadline is disabled. A 10-minute inactivity reminder uses the last effective model/tool progress; it leaves the turn running. Heartbeats and polling do not extend progress. Use Stop to interrupt manually. Source changes may show a refresh reminder; backend/MCP/dependency changes require a restart.

Historical screenshots

Images under docs/images are archived evidence from earlier development, including Chinese conversations and abandoned layouts. They are not current UI previews or default application content. The original binary evidence is retained rather than rewriting past user messages.
