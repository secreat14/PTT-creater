# Saplingagent chat frontend

The PPT reader's Speaking tab is defined as current-slide content introduction and presentation analysis. It explains the page purpose, suggests what to say, identifies up to three priorities, lays out opening/development/transition guidance and estimates speaking length. The current frontend derives these suggestions from the representative slide title, summary, points, note and next-page title, so they follow compatible in-memory edits. This establishes the display contract for future model-generated analysis without claiming that the present implementation sends a live AI request.

The main application canvas is a PPT deep reader while the existing AI chat remains docked independently on the right. The PPT workspace itself has no AI action button or AI reading card. Its Files browser is a separate left overlay sidebar, not part of the slide thumbnails. Collapse it to a narrow Files tag; drag the tag vertically or use its Up/Down arrow keys to reposition it, then click it to restore the drawer. It can choose a local directory, enter child folders, return to the previous folder and list only folders plus `.ppt`/`.pptx` files. Folder access is user initiated and remains in the browser session; selecting a PPT does not yet parse or replace the representative slide content. The reader currently demonstrates the analyzed twelve-slide TCH matrix course deck with local representative content and interactive reading controls. Edit Content now uses a WPS-style flat object model: every visible heading, summary, individual key point, tag line and newly inserted text item is its own independent text box. The editor does not group several content fields into one component or expose file/source categories inside the object inspector. A text box has one content editor plus its own X/Y/width/height, font size, weight, alignment and tone controls. It can be selected, moved, corner-resized, deleted and edited directly by double-clicking on the canvas; new text boxes can be inserted from the toolbar. Local PNG/JPEG/WebP/GIF/SVG images up to 10 MiB can be inserted with the toolbar or dropped onto the editing canvas; image objects can be selected, dragged, corner-resized, precisely positioned/sized, renamed for accessibility, replaced and deleted. Text and image objects render in thumbnails and Presenter mode but remain session-only. The Presenter mode button opens a separate presentation window with the current and next slide, speaker notes, timer and fullscreen control, and receives the current in-memory edited deck when BroadcastChannel is available. Use Arrow/Page keys or Space to move, `F` for fullscreen, `N` for notes and `R` to reset the timer. Opening, converting and writing arbitrary PPT/PPTX files remains a later integration.

The starting page provides a right-side conversation panel, independent application content and kernel operation controls. It uses React19.3.0 and assistant-ui0.15.26 with the public Agent HTTP/SSE API. No business dashboards are preloaded.

## Chat controls

- Choose a saved conversation by title/date; titles sort using Chinese pinyin/English and natural numeric order. Refresh reloads history. Rename accepts1–200 characters and saves locally through the Agent. New conversation preserves old history.
- Switch away from a running conversation without cancelling its backend run. Returning restores its snapshot and event stream. The selector becomes available after the snapshot loads; switching never resends a prompt.
- Draft text and attachments remain associated with their own conversation in page memory. Completed uploads reuse their local IDs; unfinished files resume by uploading when their draft is reopened. Page reload/restart restores only the current text draft; unsent attachments need reselection.
- The context meter displays measured tokens and reported capacity when available. It is not a billing meter and does not predict when the provider compresses context. Unknown usage stays unavailable, including providers that do not report capacity.
- Markdown supports GFM tables/task lists and inline/display mathematics, with local KaTeX fonts. Dollar currency remains text. Raw HTML and trusted TeX commands are not enabled.
- Collapse keeps the chat mounted; reopen returns focus to the composer. Drag the edge tab vertically or use its arrow keys to move it. Position storage is optional and contains no conversation content.

Existing file/image attachments, streaming, Stop/Retry, three engine selections, page inspection, restart draft recovery and Full Access remain. Accounts and model entitlement are configured in the independent kernel setup page. This UI does not read secrets or impose filesystem permissions.

## Run and verify

Use `bash Saplingagent.sh` or the exported app from the complete project. Open the actual allocated URL printed by the launcher;5173 is a starting port. For frontend-only development, run `npm ci`, `npm run dev -- --port 5173` in this directory with an Agent on the configured loopback port. Vite proxies `/api` to that Agent.

`npm run build` runs TypeScript and Vite; `npm test` runs isolated frontend/SSE/session regressions. Dependencies/cache/build outputs remain project-local and ignored. Production static output requires a same-origin Agent proxy. Messages persist in backend/workspace; browser storage contains an opaque active-session ID, launcher position and temporary restart text.
